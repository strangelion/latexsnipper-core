## Evidence Report Template

Each model category requires a completed evidence report before GA. The report
must be generated by running the evaluation pipeline and must include:

```bash
# Generate evidence for a specific tier
cargo run -p latexsnipper-evaluation --bin ocr-eval -- \
  evaluate --index evaluation/corpora/index.json \
  --predictions <predictions.json> \
  --gates evaluation/gates/pull-request.json \
  --tier <tier> \
  --source-commit $(git rev-parse HEAD) \
  --generated-at-utc $(date -u +%Y-%m-%dT%H:%M:%SZ) \
  --output target/evidence/<category>-evidence.json
```

### Required Evidence Fields

For each model category, the evidence report must contain:

```json
{
  "model": {
    "family": "<model family name>",
    "version": "<model version>",
    "source": "<upstream source URL or repository>",
    "license": "<license identifier>",
    "artifact_sha256": "<SHA-256 of model archive>",
    "artifact_size_bytes": <size>,
    "input_shape": ["<input dimensions>"],
    "output_shape": ["<output dimensions>"],
    "runtime": "<onnxruntime|tract>"
  },
  "corpus": {
    "id": "<corpus identifier>",
    "digest": "<corpus manifest SHA-256>",
    "sample_count": <number of test samples>
  },
  "metrics": {
    "accuracy": <float>,
    "precision": <float>,
    "recall": <float>,
    "f1": <float>,
    "cer": <float>,
    "wer": <float>
  },
  "runtime": {
    "provider": "<cpu|cuda|webgpu>",

    "inference_time_ms": <number>,
    "first_inference_ms": <number>,
    "warm_inference_ms": <number>
  },
  "platform": {
    "os": "<windows|linux|macos>",

  },
  "known_failures": [
    {
      "sample_id": "<id>",
      "reason": "<description>",
      "severity": "<low|medium|high>"
    }
  ]
}
```

## How to Generate Evidence

### Step 1: Run Pull-Request Tier Evaluation

```bash
# This uses the PR-level gates and produces a baseline
cargo run -p latexsnipper-evaluation --bin ocr-eval -- \
  validate --index evaluation/corpora/index.json
```

### Step 2: Run Scheduled Tier Evaluation

```bash
# Trigger the Scheduled hardening workflow
gh workflow run scheduled.yml
```

This produces:
- Benchmark regression JSON
- libFuzzer smoke results
- Production model WASM execution results
- Model URL verification results

### Step 3: Generate Release Evidence

```bash
# For each model category, generate release-tier evidence
for category in formula-det formula-rec text-det text-rec table-det table-struct; do
  cargo run -p latexsnipper-evaluation --bin ocr-eval -- \
    evaluate --index evaluation/corpora/index.json \
    --predictions target/predictions/${category}.json \
    --gates evaluation/gates/release.json \
    --tier release \
    --source-commit $(git rev-parse HEAD) \
    --generated-at-utc $(date -u +%Y-%m-%dT%H:%M:%SZ) \
    --output target/evidence/${category}-evidence.json
done
```

### Step 4: Verify Evidence Against Manifest

```bash
# Verify each evidence report matches the model manifest digest
python scripts/verify_v3_contract_freeze.py
```

### Step 5: Archive Evidence

```bash
# Copy evidence to release artifacts
cp -r target/evidence/ release-evidence/
git add release-evidence/
```

## Known Limitations

These are documented limitations, not bugs. They must be listed in release notes:

1. **Unicode text rendering:** Characters outside WinAnsi range degrade to `?`
   in PDF export. Full Unicode font embedding is a post-GA task.
2. **Formula rendering:** Core SVG generator produces visual text approximation,
   not mathematical layout. MathJax or external renderer recommended for
   high-fidelity output.
3. **Table recognition:** TATR models are optimized for academic PDFs. Complex
   merged cells or nested tables may have reduced accuracy.
4. **Image quality:** PNG export uses fixed 96 DPI. High-DPI rendering is not
   yet supported.
