# 个性化公式补全与辅助续写计划

更新：2026-10-15。先完善 Core 的结构化候选，再评估可选排序后端；模型接入与训练不作为当前收尾门禁。

## 当前基础

Office 已有命令/环境/上下标模板、有限光标上下文联想和有效保存符号候选。
最佳候选以淡字显示，Tab 接受、Esc 隐藏、Ctrl+Space 唤出，接受可一次撤销。
菜单跟随深浅主题；本地频率/最近使用排序默认关闭，可关闭和清空。
Core 已有带源码范围的有限 LaTeX 编辑结构、槽位、环境/矩阵位置、候选编辑及快照复验的 Rust 接口。
JSONL/C/Python/WASM-JS 已接查询/接受候选，共享有界请求、精确版本字符串与简明快照；
JS Worker 队列/取消/超时及字符边界转换已有；Rust/C/Python/JSONL 另有有限自定义签名和定义/作用域/重置代数复验。
WASM-JS 的作用域扩展、实际编辑宿主及更多命令/定界符仍需补齐；见 [接口边界](formula-completion.md)。
Office 当前候选规则和偏好排序仍在前端实现，尚未切换到此 Core 接口；当前没有具体学习模型或生成式续写。

## 职责与顺序

Core 先提供可复用的结构上下文、合法候选、编辑范围、占位符与排序接口。
Office/Web 等宿主随后负责候选展示、Tab/撤销、设置、请求节流和反馈授权，复用 Core 的结果。
Jev AI 作为后续可选决策/评分后端评估；具体型号、调用限制、延迟和费用在评估时核对官方接口并实测，
不据外部示例作本应用性能承诺。先比较排序收益，有足够且已授权的编辑反馈后再评估训练。

## 实现边界

- Core 保持确定性语法、资源预算、支持范围和损失检查；偏好分数不能绕过这些检查。
- 建议绑定当前编辑版本，迟到结果不得覆盖新输入；宿主负责选区、事务和写入确认。
- 默认不上传公式；只保存最小化、有界、可解释的反馈，不持久化原始公式或私有符号名。
- 模型、历史或存储失效时回退确定性补全，不阻塞编辑、渲染和转换。
- 真实 IME、长文档响应与实际节省输入的收益尚待确认，不能把候选数量当学习效果。
- 续写不代表数学证明；不自动替换已有公式或写入 Office，不添加强制推理依赖。

优先推进 SC-01/02 的 Core 基础；其他应用接入和模型评估随后安排。
格式补全与现有安全/适配工作继续推进，安装信任和真实宿主验收独立保留。
